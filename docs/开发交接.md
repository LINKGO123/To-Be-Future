## 一、架构与文件

### 1.1 项目定位

A 股「跟资金动向型」个人投研工作台。面向 60 岁、跟随资金动向（游资 / 主力 / 涨停梯队）投资科技股的股民，输出大白话、结论前置、短句易读、语音 ≤90 秒的内容。品牌为 To Be Future，视觉为 DSH 蓝主题 + A 股红涨绿跌 + 四档字号。

### 1.2 三层架构

| 层 | 目录 | 技术 | 职责 |
|---|---|---|---|
| 前端 | `desktop/` | React 19 + Vite 6 + TypeScript，Tailwind / zustand / echarts / react-router-dom 7 | 垂类页面、组件、业务逻辑；`@` 别名指向 `desktop/src/verticals/finance/` |
| 后端 | `orchestrator/` | Node ≥22.18 + TypeScript（`node -e` 直跑 `.ts`），`@openai/codex-sdk` 0.153.4 | 薄 HTTP API + WebSocket，鉴权、路由、研究编排、语音转写、模型通道 |
| 数据层 | `calc/` + `datasources/` + `.agents/skills/data-access/scripts/` | Python | `calc/` 确定性计算函数；`datasources/` 数据源注册表 / 目录；`scripts/` 取数脚本（`sources/` 下各数据源实现） |

### 2.2 本地开发启动

**Windows（家人模式一键启动）**：双击 `启动资金雷达.bat`，或 `powershell -ExecutionPolicy Bypass -File 启动资金雷达.ps1`。

该脚本做的事（对应用 Mac 手工启动时的两步）：

1. 注入 bundled node 到 PATH；
2. 起后端：`node orchestrator\src\api.ts --port 8765 --host 127.0.0.1`；
3. 起前端：`node <pnpm.mjs> --dir desktop run dev`（固定端口 5930）；
4. 经前端代理跑健康检查（`orchestrator\src\startup_health.ts`）直到通过；
5. 打开 `http://127.0.0.1:5930`；任一进程退出按进程树清理（`scripts\start.ps1` 同款）。

**Mac 手工启动（等价两步，两个终端）**：

```bash
# 终端 1：后端（首次启动会生成 .local/api.token，Vite 每次请求重读该文件）
node orchestrator/src/api.ts --port 8765 --host 127.0.0.1

# 终端 2：前端（Vite 读取 .local/api.token，代理 /api → 127.0.0.1:8765 并注入 Bearer）
pnpm --dir desktop dev
```

> 鉴权机制：Bearer token 只留在本机进程，浏览器永远不碰。开发期由 Vite 代理注入（`desktop/vite.config.ts` 每次请求重读 token 文件）；打包后由 Electron 主进程内置反代注入（`electron/main.cjs`）。token 来源优先级：环境变量 `VRA_API_TOKEN` > 后端生成的 `.local/api.token`。
> 注意 `localhost` 在本机可能解析成 `[::1]`，而后端绑 `127.0.0.1`，所以 Vite `host` 已写死 `127.0.0.1`（否则 502）。

## 三、踩坑与解法

### 3.1 东财 push2 断连 = 封 IP

| 项 | 内容 |
|---|---|
| 现象 | 批量 / 高频请求东财 `em_*` 端点后，push2 系接口断连、返回空数据 |
| 根因 | 东财系共用同一风控面，批量请求触发封 IP（约 30–60 分钟解封，a-stock-data 实测结论） |
| 解法 | `fundradarData.ts` 对所有 `em_` 前缀端点做全局串行化 + 最小间隔节流（`EM_THROTTLE_MS = 500` ms，任何时刻最多一个 `em_` 请求在途；缓存命中的 `em_` 不真发请求）。腾讯 / 新浪 / baostock 不封 IP、不限流。备用源：`sina_fund_flow`（新浪资金流）、`exchange_dragon_tiger`（交易所龙虎榜官方：深交所结构化 + 上交所全文，见 `data-access/scripts/sources/exchange.py`） |

### 3.2 Electron 无 Web Speech 后端

| 项 | 内容 |
|---|---|
| 现象 | Electron 里 `SpeechRecognition` / `webkitSpeechRecognition` 不可用，语音输入失效 |
| 根因 | Chromium 无可用 Web Speech 后端（Web Speech 依赖 Google，国内连不上） |
| 解法 | 本地 sherpa-onnx 离线 STT，两条路径并存：非流式 `transcribe.ts`（paraformer 中文小模型，录完 WAV 一次性识别）+ 流式 `transcribe_stream.ts`（zipformer 双语流式模型，边录边出 interim/final）。前端 `VoiceInput.tsx` 在 Electron 或浏览器不支持 Web Speech 时改用 `getUserMedia` + `AudioContext` 录 16kHz/16bit/单声道 WAV，交本机后端识别 |

### 3.3 流式 STT `ModuleNotFoundError: sherpa_onnx`

| 项 | 内容 |
|---|---|
| 现象 | 流式语音识别一启动就报 `ModuleNotFoundError: No module named 'sherpa_onnx'` |
| 根因 | `sherpa_onnx` 装在 `resources/python` 便携解释器里，但后端 `ctx.python` 指向仓库 `.venv`（`.venv` 只有数据层依赖，没有 sherpa_onnx） |
| 解法 | `transcribe_stream.ts` 的 `pythonExe()` 优先用便携解释器：`resources/python/python.exe`（win）/ `resources/python/bin/python3`（mac），再回退 `ctx.python` → `VRA_PYTHON` → 系统 python |

### 3.4 Windows 中文路径让 `sherpa-onnx-offline.exe` 窄 argv 挂掉

| 项 | 内容 |
|---|---|
| 现象 | 仓库在 `D:\AI工具\股票工作区\...`、用户名 `刘德华`，绝对中文路径必挂（退出码 -1，模型 / wav 打不开） |
| 根因 | `sherpa-onnx-offline.exe` 用窄 `main(argc, char* argv[])` 收参，Windows 按 ANSI 代码页（GBK 936）把中文路径转窄字节，`std::ifstream` 再转回宽字符时对不上 |
| 解法 | 模型 + wav 缓存到 `os.tmpdir()/fr-stt-model`；spawn 时 `cwd` 指向该缓存目录（Node 用宽字符传 cwd，中文没问题）；argv 只传相对 ASCII 文件名（`tokens.txt` / `model.int8.onnx` / `audio-<rand>.wav`）。详见 `transcribe.ts` 文件头注释，此设计必须保留 |

### 3.5 DSH 沙箱 spawn EPERM / 路径含空格 `-File` 截断

| 项 | 内容 |
|---|---|
| 现象 | 在 DSH 沙箱内 spawn 子进程捕获输出报 EPERM；PowerShell `-File` 传含空格路径时被截断 |
| 根因 | 沙箱禁止打开命名管道（`child_process.spawn` 默认 `stdio: 'pipe'` 走管道捕获即 EPERM）；`-File` 对含空格 / 中文路径需正确引用 |
| 解法 | 分离进程用 `Start-Process powershell -Command "& '路径'"`（单引号包裹含空格路径），避免管道捕获子进程输出；不要对同一命令反复换姿势重试（EPERM 是文档化边界）。参考 `启动资金雷达.ps1` 的 `Start-Process` 用法 |

### 3.6 electron-builder GitHub publish 双重 draft（资产拆散）

| 项 | 内容 |
|---|---|
| 现象 | 发布后 GitHub Release 出现两个 draft，安装包资产被拆散到不同 draft，自动更新拉不到正确资产 |
| 根因 | electron-builder 发布与手动新建的 draft 重复，资产未合并到同一 Release，draft 状态未收敛 |
| 解法 | 发布后核对目标 Release 是 `draft=false`；若拆散，手动修：删除 stray draft → 重传 asset 到正确 Release → `PATCH` 该 Release `draft=false`。发布命令见 2.6 |

### 3.7 单实例锁二次启动打不开

| 项 | 内容 |
|---|---|
| 现象 | 关窗后立刻再点，窗口不出现（看起来「打不开」） |
| 根因 | `cleanup` 的 `taskkill` 曾用 `spawnSync` + 8 秒超时同步阻塞 `app.quit()`，单实例锁释放延迟；二次启动 `requestSingleInstanceLock()` 返回 false → 直接 `app.quit()` |
| 解法 | 三处配合（`electron/main.cjs`）：`taskkill` 改异步（`spawn` + `unref()`）；`will-quit` 显式 `app.releaseSingleInstanceLock()`；加守护层 `GUARDIAN_SCRIPT`（主进程给守护进程 stdin 开管道，主进程死亡即杀后端整棵树） |

### 3.8 GitHub 推送被拒（workflow scope）

| 项 | 内容 |
|---|---|
| 现象 | 推送被拒，报 workflow scope / token 权限不足 |
| 根因 | 仓库内 `.github/workflows`（学习资料自带 CI）需要 workflow 权限，与所用 token scope 不符 |
| 解法 | `.gitignore` 已排除 `.github/workflows/`（学习资料不推 CI，本地保留即可）。注意：`AGENTS.md` 要求 GitHub Secret Scanning 与 Push Protection 保持开启，不因推送受阻而关闭平台防护 |

### 3.9 语音 network error 后状态卡住 + 停止按钮失效

| 项 | 内容 |
|---|---|
| 现象 | Web Speech 触发 `network` 类错误后，录音状态卡住（红框 / 波形 / 计时不复位），停止按钮失效 |
| 根因 | `onerror` 未全分支重置状态，识别实例残留 |
| 解法 | `VoiceInput.tsx`：`onerror` 统一收尾（退出录音态、清识别实例，保证停止按钮 / 红框 / 波形都能复位）；`network` / `service-not-allowed` 错误写 localStorage `fr-voice-use-local=1`，此后一律记忆式降级本地 STT（不再反复试 Web Speech） |
